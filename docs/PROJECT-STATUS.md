# Project status and known limitations

This repository is an early public alpha. The following boundaries are deliberate and should remain visible in documentation and user-facing output:

- Caido 0.58.3 with the pinned community MCP bridge v4.3.0 and the current Go capture schema v5 / BehaviorGraph schema v2 have been exercised in one development environment. The latest read-only reconciliation enumerated 1,369 Caido IDs against 477 local IDs: 477 matched, 892 were Caido-only, and none were local-only or duplicated. Intake is incomplete; compatibility across Caido versions and workspaces is not established.
- Caido does not currently provide a stable history snapshot token to this workflow. A completed metadata enumeration therefore cannot prove that the source was unchanged throughout the read; reconciliation reports `PARTIAL`.
- Some imported exchanges have incomplete parse or response-body coverage. HTTP status or endpoint presence alone is not a complete behavioral analysis.
- Browser walkthrough and JavaScript endpoint coverage are not yet part of a complete end-to-end application-map workflow.
- The project-local KB index is an FTS5-only snapshot with 14,300 documents and 16,961 chunks across five populated source families. NVD remains `PARTIAL` after a provider failure; ExploitDB remains `BLOCKED` pending dataset-terms review. SQLite integrity and foreign-key checks pass, but the runtime directory lacks the source manifest and JSONL inputs needed to revalidate source hashes and chunk spans. No compiled corpus is included in Git.
- Hermes is an experimental harness integration; it is not a supported, end-to-end hypothesis-analysis loop.
- Candidate hypotheses and graph relationships are not confirmed findings. Evidence validation and human review remain necessary.

## Latest local integration checks (2026-10-22)

- The Go runtime opened the working capture and graph stores read-only and reported capture schema v5 and BehaviorGraph schema v2 compatible. The latest project audit counted 477 captures, all search-indexed and graph-mapped; parsing is complete for 155, partial for 322, and unparsed for 0. Request-message fidelity is `reconstructed_text` for all 477 captures (0 source-byte copies); response fidelity is reconstructed for 463 and unknown for 14. The imported text is therefore not a byte-exact copy of the original Caido wire messages.
- A bounded read-only Caido reconciliation enumerated 1,369 IDs in 14 pages. It found 477 matched, 892 Caido-only, 0 local-only, and 0 duplicate IDs. Coverage remains `PARTIAL`: Caido provides no stable snapshot token or expected total, and 892 currently listed IDs are absent locally. Historical backfill reports terminal `state=done` separately from `coverage_reconciled=false`; a synthetic regression test protects that distinction.
- The local historical index contains 477 captures; the live index is empty. A prior bounded live-tail cycle completed one page with `idle` and 0 new requests. This verifies only the no-new-data path; ingestion of new traffic and a persistent background worker are not verified.
- The project-local KB snapshot has 5 populated source families, 14,300 documents, and 16,961 FTS5 chunks and reports `PARTIAL`. SQLite returned `integrity_check=ok` and zero foreign-key violations, but the runtime directory has no snapshot manifest or source/chunk JSONL files, so source-hash and chunk-span validation could not be repeated. NVD coverage is `PARTIAL` after `provider_failed:ValueError`; ExploitDB is `BLOCKED` pending dataset-terms review. The generated Hermes profile now carries the configured private data root and optional KB index path; a read-only MCP `bb_kb_stats` call returned the expected snapshot ID and counts. No source excerpts were read for this check.
- A separate one-day NVD API canary for the 2026-10-21/22 window fetched and parsed all 531 expected CVE rows and recorded two notices. It was diagnostic only and was not imported into the local index. The 730-day provider failure remains unexplained, so NVD coverage remains `PARTIAL`.
- Go KB regression tests now build a synthetic database with the Python FTS5 schema and verify stats, filtered search, source retrieval, truncation and content-hash behavior. They also assert that read operations leave the index bytes unchanged and that a missing index is not created.
- Hermes discovered the eight configured read-only tools. Its model provider is not configured, so the model-backed analysis and hypothesis cycle has not been verified.

Contributors should preserve explicit `PARTIAL` and `BLOCKED` states whenever data, coverage, or source provenance is missing.
